03 — Componentes

Componentes de UI

Cada exemplo abaixo é o componente real, extraído com suas classes originais. O site não define nenhum :hover/:focus/:active em CSS (checamos: 2 ocorrências de :hover no HTML inteiro, e nenhuma pertence ao design — uma é motor interno do Framer, outra é a barra de edição). A resposta a hover/press é feita por variantes do Framer Motion em tempo de execução, não reproduzível de forma estática — por isso mostramos aqui apenas os estados que realmente existem na marcação: default, active e disabled.

05 — Comportamento

Movimento & Interação

O site não usa @keyframes CSS para as entradas (só existem dois @keyframes no arquivo inteiro, ambos de infraestrutura do Framer, não do design). Toda animação de entrada é feita em runtime pelo Framer Motion, que anima opacity e transform inline com física de mola (spring). A galeria abaixo reproduz fielmente os valores reais capturados no JSON de animação do próprio arquivo — dispare o scroll para ver.

Outras interações presentes (não reproduzíveis sem o runtime React da Framer)

  • Contador numérico — "365", "12", "100%" contam a partir de zero na entrada (ver seção 0 e grid acima).
  • Carrossel de depoimentos — troca automática entre 3 cards com transform e visibility, mais setas prev/next.
  • Acordeon do FAQ — expande a resposta e gira o ícone chevron ao clicar na pergunta.
  • Popup do WhatsApp — alterna entre ícone e X, revela a caixa de mensagem com fade.

06 — Elementos

Ícones

O site usa dois sistemas de ícone lado a lado: um sprite <symbol> compartilhado (referenciado via <use href="#svg-…">, definido uma vez e reaproveitado) e ícones inline path soltos nos componentes de código (emoji, enviar). O tamanho é sempre controlado pelo container pai (width/height:100% no próprio <svg>), então variantes de tamanho vêm de redimensionar o wrapper — não do ícone.
